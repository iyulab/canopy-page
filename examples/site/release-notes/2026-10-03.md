# Dated pages, and sections you can follow

## A page says when it was published

A page whose frontmatter names a `date:` now shows it under its heading, spelled in the site's
language — the line under this page's title comes from exactly that:

```markdown
---
date: 2026-10-03
---
```

The same date reaches search engines: `article:published_time` (and `article:modified_time`, from
`updated:`) in the page's `<head>`, and a schema.org `Article` record with the headline,
description, dates and language. A page without `date:` is unchanged.

## A feed for a section

```json
{ "path": "release-notes", "order": "desc", "feed": true }
```

publishes `release-notes/feed.xml`, an Atom feed of the section's dated pages, newest first, and
links it from every page in the section so a browser or a feed reader finds it. It needs
`siteUrl`, since a feed's links are absolute. These release notes are the demonstration: each one
is dated, and the section has a feed. See [Feeds](../reference/settings.md#feeds).

## `check` watches the dates

Two new warnings: a `date:` or `updated:` that is not a date (`2026-02-30`, `28/09/2026` — the page
would render as undated), and a page in a feed section with no `date:`, which the feed would
silently leave out.

## Sitemap dates follow the same rule

A sitemap `<lastmod>` taken from `updated:` now uses the renderer's own rule for what is a date,
so a page the renderer considers undated never gets a date in the sitemap — and an `updated:`
written as a date-time names its day.

## Upgraded to canopy 0.17.0

All of the above is canopy's — canopy-page turns `"feed": true` into canopy's `--feed` and checks
dates with canopy's own rule.
